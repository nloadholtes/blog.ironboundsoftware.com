---
title: "First principal: Old dogs, new tricks"
date: 2026-11-23
---

While it looks like AI is transforming the profession of Software Development, this weekend I had a minor revelation: It is actually stripping away the cruft.

Let me explain. For decades a lot of developer thinking was around things like languages and tools and techniques. At the time and in the environment we were working in, this was a very reasonable thing to think about!

Place with a repuation for difficult interviews, think FAANG companies, liked to use Computer Science questions in their interviews. And a lot of us devs like to complain that we "use libraries, not retype a binary search by hand everytime". Now adays the LLMs could do either approach and most wouldn't notice the difference: the human element that could introduce error in the hand-coded version is now basically gone.

But is the resulting code correct? I think arguably yes it. We have tests, we have fuzzing, we can rapidly deploy and test and roll back if necessary.

So what remains?

The core ideas.

If we as developers go back to more first principals thinking as we work with our agents, I think we will begin to feel more engaged with our work.

Ask how we can verify a new feature is working as expected.

Ask if the latency introduced by a design is worth the tradeoffs.

Ask if we've optimized the general case, or some edge cade.

Basically all the things so few of us asked about before, are now probably the main things we should be thinking about and working towards.
